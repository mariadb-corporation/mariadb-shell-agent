# Project context: mariadb-code

## Project

A fork of [Qwen Code](https://github.com/QwenLM/qwen-code) rebranded as **MariaDB Shell Agent** (former name MariaDB Code / `mariadb-code` / `mdbc`; the NAS repo
is `mariadb-shell-agent`; nothing migrates from `~/.mariadb-code`): the CLI
(`mariadb-shell-agent`, short `msa`), the VS Code extension `MariaDB.mariadb-shell-agent` (used in desktop VS Code and
in the Theia-based MariaDB Cloud Workbench of the sibling `mariadb-workbench` repository) and the daemon's Web
Shell. The fork follows upstream closely (rebased as soon as upstream moves), ships no Alibaba endpoints and
does not identify itself as Qwen Code to anyone. The maintenance workflow is documented for humans in
`mariadb/README.md`.

## Architecture / key decisions

- **Upstream files are never edited by hand.** `main` = an upstream commit + fork commits that touch only
  `mariadb/` (and `.claude/`, force-added because upstream's `.gitignore` ignores it) + one generated top
  commit "MariaDB branding (generated by mariadb/rebrand.mjs)", whose body records the upstream base
  (`Upstream: <sha>`). Fork commits never conflict on rebase (upstream has no such paths).
- **`mariadb/sync-upstream.sh [--to <rev>] [--verify] [--push]`**: fetch, drop the generated commit,
  cherry-pick the fork commits onto `upstream/main` (or `--to <rev>` when upstream `main` does not build),
  run `rebrand.mjs`, commit, `corepack pnpm install --frozen-lockfile`, leak scan, optional test gate,
  `--push` = `git push --force-with-lease NAS main` (history is rewritten every sync).
- **`mariadb/rebrand.mjs`** runs rule modules from `mariadb/rebrand/` in order: `patches`, `identity`,
  `version`, `product-name`, `name-length`, `artwork`, `alibaba`, `paths`, `cli-name`, `extension-ids`, `review`, `outbound`,
  `skipped-tests`. Helpers in `lib.mjs`: `patch()` must find its anchor (skips when `alreadyDone`),
  `replaceInTracked()` (string or RegExp pairs, never touches lines containing "copyright"), `rename()`
  (moves files and maps git-listed paths), `skipTests()`. A rule whose anchor upstream removed stops the
  run. The script is idempotent (a second run changes 0 files).
- **Own code changes = patch files** in `mariadb/patches/` (explanation text above the first
  `diff --git`), written against pristine upstream, applied first with `git apply --3way`, only on a
  pristine tree (skipped when the extension manifest already has publisher `MariaDB`). A real conflict
  stops the sync; redo the patch against the new code. Write a new patch in a separate worktree, not in
  the branded tree: `git worktree add --detach <dir> <upstream base>`, apply all existing patches with
  `git apply --3way` (stages them), edit, then `git diff` against that index (new files via
  `git add -N`) above the explanation text; prettier only the touched files and check the diff has no
  unrelated reformatting. Then commit the patch in `mariadb/` and run `mariadb/sync-upstream.sh`. For a
  quick test before that, `git apply` the plain diff to the branded tree and `git checkout -- packages`
  afterwards (hunks whose context the rebrand changed, e.g. in `strings.ts`, don't apply: `--exclude`
  them and edit by hand). To change an existing patch whose files later patches don't touch, apply the
  patches before it with `--3way` (staged), the patch itself with plain `git apply`, edit, and
  `git diff` the patch's own file list (`git add -N .` for its new files) under its explanation text.
  A hand-edited `.patch` needs its `@@` line counts adjusted. In zsh pass file lists as
  arrays (`F=(a b); git diff -- "${F[@]}"`), a plain variable is not split into words.
  - `0001` context-file markers in the system prompt use `~/…` for home files (were cwd-relative).
  - `0002` one system prompt opening ("a CLI agent") for headless/interactive/ACP; the mode is named in
    the closing "Interaction mode reminder". Modes share ~99% of the prompt; a test pins it.
  - `0003` daemon bridge for browser-based hosts (`vscode.env.uiKind === Web`: Theia, code-server, VS Code
    for the Web): `webShellBootstrap` carries `daemonBridge: true`; `src/webview/daemonFetchBridge.ts`
    (imported first in `webview/index.tsx`) wraps `fetch` and sends requests to the daemon origin as
    messages; `src/services/daemonFetchBridge.ts` forwards only to the daemon's origin and streams the
    response back. Desktop windows are unchanged. Web Shell features with their own WebSockets
    (terminal, live browser, voice, local files) are not bridged.
  - `0004` the main session's "Interaction mode reminder" is the first part of the startup prelude
    (`getMainSessionInteractionModeReminder`, option `interactionModeReminderInPrelude`) instead of
    the end of the system prompt; Arena agents keep it in the system prompt, prompt overrides get none.
  - `0005` `getFunctionDeclarations`: revealed deferred tools follow the name-sorted rest in reveal
    order (a `tool_search` reveal only appends).
  - `0006` managed-memory extraction and dream start after 10 idle seconds in interactive and ACP
    sessions (`QWEN_CODE_MEMORY_EXTRACT_IDLE_MS`); a new question restarts the wait; headless runs
    start them at once; a pending start is dropped on shutdown. ACP's default path (`Session.ts`,
    unified agent loop off) calls the client's public `scheduleManagedMemoryRun()` and, on a fresh
    prompt, `clearPendingManagedMemoryRun()`, so both paths share one pending start.
  - `0007` the transcript also records each UserQuery/Cron prompt as sent (system record
    `sent_user_content`, written in `client.ts` right before `turn.run`; parts equal to the user record
    stored as `{ recordedPart: i }`), and the history rebuild (`session-api-history.ts`) puts them back,
    so CLI `--continue`/resume replays the reminders (date, plan mode, output style, memory recall, IDE
    context) unchanged. Tool-result-turn reminders are not covered; ACP records only the prompt text
    itself, so ACP session resume is unchanged.
  - `0008` (catalog stays where it was first sent) retired 2026-10-28: upstream #15246 does the same
    (marked `memory_catalog_snapshot` parts kept in history, appended only on change, recorded and
    replayed); the number stays unused.
  - `0009` web-shell composer: no dotted aura/halo around the focused composer (`.dacAura`, `.dacHalo`
    hidden), no glow on the send button, whose arrow is the execute bolt of the MariaDB VS Code
    extension in `currentColor` (`SendIcon` in `ChatEditor.tsx`).
  - `0010` no "Open" button (`openChat`) in editor title bars.
  - `0011` Claude plugin conversion: a plugin.json `mcpServers` file path in `.mcp.json` format is
    unwrapped (servers were nested under one server named `mcpServers`); a root `.lsp.json` becomes
    `lspServers` when plugin.json declares none (Claude Code's convention).
  - `0012` extension setting `mariadb-shell-agent.experimentalLsp` (off by default) adds `--experimental-lsp`
    to the daemon (`serve`) and ACP spawns; the flag is the CLI's only LSP switch.
  - `0013` LSP discovery runs in `loadCliConfig` before `Config.initialize()` loads extensions, so
    extension LSP servers were never found at startup; `initialize()` now calls
    `refreshLspAfterExtensionsLoaded()` (background `reinitializeLsp`, not awaited: server startup can
    take minutes).
  - `0014` extension `.lsp.json` entries with `extensionToLanguage` are keyed by server name (Claude
    format); a project's own `.lsp.json` stays keyed by language.
  - `0015` no "Companion extension successfully installed." notification on first activation
    (product choice; the extension's own `showInformationMessage`, not VS Code's install notice).
  - `0016` extension provider setup: nothing starts on first load; Get Started, `/auth` or the auth
    command opens a wizard in the webview (`components/AuthWizard.tsx`, descriptors from
    `describeWizardProvider` in `handlers/AuthMessageHandler.ts`, types in `authWizardTypes.ts`) with
    the old QuickPick/InputBox steps (provider → protocol → API → base URL → key → models → thinking,
    per `shouldShowStep`). Messages `authWizard` / `authWizardSubmit` / `authWizardCancel` /
    `authWizardError` (validation, wizard stays open) / `authWizardDone` (always last); `authError`
    also keeps it open; `WebViewProvider` replays an open wizard on `webviewReady`. Adds the core
    preset `openai` ("OpenAI API Key", `OPENAI_API_KEY`, Responses API at `https://api.openai.com`
    without `/v1`, default model `gpt-6.1-sol`, editable; owns only `[OpenAI] …` models, so hand-made
    `OPENAI_API_KEY` models survive an install). Welcome title: 32px, the Web Shell product-name
    gradient (`TITLE_GRADIENT`, exported from `QwenOnboarding.tsx`); every wizard page starts with
    the icon and product name in that gradient, subtitled "Provider Setup Wizard" (`wizard.title`).
  - `0017` GPT-6 models (per developers.openai.com/api/docs/models): reasoning controls for
    `gpt-6.1-sol` (thinking mandatory, like upstream's `gpt-6-astra`), `gpt-6.1-terra` and
    `gpt-6-luna` (accept `none`, so thinking can be switched off); `/^gpt-6/` token limits 922K input,
    128K output (were the generic GPT fallback, 128K/16K).
- **Alibaba removal (`alibaba.mjs`)**:
  - Alibaba-run hosts (aliyuncs, aliyun, alibabacloud, alibaba-inc, qwen.ai/.com, qwencloud(api),
    modelscope, …) get TLD `.invalid` in shipped code, tests and docs (also escaped regex spellings,
    case-preserving). QwenLM GitHub/docs/ghcr URLs likewise, except `/review` test sample data and the
    managed-runtime contract `$id`s; the CSI driver name `diskplugin.csi.alibabacloud.com` stays.
  - Alibaba presets stay registered (reasoning overrides, the extension's plan definitions and web search
    look them up) but are filtered out of the picker groups, the ACP provider list, the Web Shell
    catalog and the CLI dialogs' main menus; the extension's Coding Plan settings are removed from its
    manifest. Offered everywhere (CLI, Web Shell, ACP, extension wizard), in this order:
    OpenRouter, Requesty, OpenAI, Grok, custom — `OFFERED_PROVIDER_IDS` in `alibaba.mjs` (ordered
    allow-list) and `AUTH_WIZARD_PROVIDER_IDS` in patch 0016. DeepSeek, MiniMax, Z.AI and Kimi stay
    registered (existing settings keep working) but are not offered; their upstream tests that walk
    to them are in `skipped-tests.mjs`.
  - Usage statistics and auto-update default off — two default paths each (`?? true` in config and in
    `resolveUsageStatisticsEnabled`; `enableAutoUpdate !== false` checks) plus schema defaults and the settings reference
    (`docs/users/configuration/settings.md`, checked by `settings-docs-sync.test`); the
    analytics endpoint is `usage-statistics.invalid` with an empty app id; dist npm name
    `@mariadb/mariadb-shell-agent` (npm self-update finds nothing); no OpenRouter/Requesty attribution headers.
- **Names**: `~/.mariadb-shell-agent` and `<project>/.mariadb-shell-agent` (the repo's own project dir is renamed too),
  `MARIADB-SHELL-AGENT.md`, `.mariadb-shell-agentignore`, commands `mariadb-shell-agent`/`msa` (also in help text and logs),
  extension ids `mariadb-shell-agent.*`, terminal title "MariaDB Shell Agent - <folder>", `/review` footer.
  `MARIADB_SHELL_AGENT_<X>` overrides `QWEN_<X>`/`QWEN_CODE_<X>` via a generated
  `packages/cli/src/mariadb-env-aliases.ts`, imported first by `packages/cli/src/cli.ts` (not `index.ts`:
  `index.test.ts` loads `index.ts` with fixture modules).
- **Outbound identity (`outbound.mjs`)**: User-Agent `MariaDBShellAgent/<version>` (model providers,
  preconnect), `mariadb-shell-agent` for downloads, MCP client name `mariadb-shell-agent-mcp-client-<server>`, ACP agent
  name `mariadb-shell-agent`, system settings paths (`/etc/mariadb-shell-agent`, `ProgramData\mariadb-shell-agent`,
  `Application Support/MariaDBShellAgent`).
- **Kept on purpose**: `QWEN_*` variable names, internal file names inside the config dir,
  `qwen-extension.json`, Qwen model names, `<!-- qwen-review -->` markers, the `Qwen-Code-CI-Bot` login,
  license headers and NOTICE files (Apache-2.0 requires them, so the code's origin stays traceable).
- **Artwork**: app icon = `mariadb/assets/app-icon.svg` + PNGs (Web Shell favicon from the SVG, sidebar
  mark `IconQwenLogo` from `icon-192.png` as a PNG data URI: the artwork has gradients and embedded
  images; the brand tests tell it from an operator logo by the data URI type); Affinity exports
  are fine as they are (`svgParts` in `artwork.mjs` strips prolog, editor ids/namespaces, turns
  styles into attributes; `seal-mono.svg` must be plain shapes, else the run stops); activity
  bar = `mariadb/assets/mariadb-shell-agent-ext.svg`, shipped as `assets/activity-bar-<sha8>.svg` because VS Code
  caches icons by URL and a same-version reinstall would keep the old one; MARIADB ASCII banner in
  `mariadb/assets/ascii-logo.txt`. Web Shell welcome screen (artwork rule): `WelcomeSeal.tsx` is
  generated from `mariadb/assets/seal-mono.svg` and shown above the title (text color), the wrapped
  title has no row gap, its subtitle (`welcome.prompt`) reads "What would you like to work on?"
  (`product-name.mjs`, anchored to the key); the product name uses mariadb.com's "Agentic Enterprise" gradient
  (`--agent-logo-gradient` in `App.module.css`: `.themeDark` #51d9f7 → #8ce786 → #cdf70a, `.themeLight`
  #0093c4 → #00a37a → #5c9f00, saturated shades with at least 3:1 contrast on white; the originals
  are unreadable there).
- **Checks**: `mariadb/check-leaks.mjs [paths|.vsix]` scans source or build output for old names (also the
  former MariaDB Code names), Alibaba and QwenLM hosts, outbound identifiers; exceptions with reasons in `mariadb/leak-allowlist.json`.
  `mariadb/verify.mjs [--quick]` runs vitest in vscode-ide-companion, web-shell, acp-bridge,
  sdk-typescript, core, cli, reruns failing files one by one twice, reruns the rest on the upstream base
  sources and reports only failures the fork causes (needs a clean tree and checks out upstream files
  mid-run, so don't edit the tree while it runs (~1 h); it `reset --hard`s at the end).
  `mariadb/rebrand/skipped-tests.mjs` lists upstream tests of removed behaviour, grouped with reasons.
- **Version**: the fork's own version is `mariadb/VERSION` (year.month.n, started at 26.10.1 on
  2026-10-28), applied only to the built packages: `build-vsix.sh` sets the extension manifest for
  the build and exports `MARIADB_FORK_VERSION`, which `rebrand/version.mjs` makes `esbuild.config.js`
  (CLI_VERSION) and `scripts/prepare-package.js` (dist package version) prefer. Sources, lockfile
  and tests keep upstream's version; native optional deps (audio-capture) keep their pins.
- **Builds**: `mariadb/build-vsix.sh` (this machine, with node-pty) or `universal` (no node-pty; for the
  Linux arm64 Cloud Workbench) → `mariadb/dist/`; it deletes the extension's `dist/` first (esbuild leaves stale
  hashed chunks that would be packaged) and leak-scans the `.vsix`. In `mariadb-workbench`,
  `npm run plugin:mariadb-shell-agent` unpacks the newest universal build, `npm run deploy:pi` builds there.

## Gotchas / things not to repeat

- `mariadb/` is tracked: `git checkout -- .`, `git reset --hard` or `git stash` wipe uncommitted rule
  edits. Commit rule changes before resetting. When iterating, reset upstream files with
  `git read-tree <base> && git checkout -- . ':!mariadb' && git clean -fd -- . ':!mariadb'` and restore the
  index with `git reset` before committing.
- The repo's pre-commit hook (lint-staged: prettier, `eslint --max-warnings 0`) also runs on the generated
  commit: `alreadyDone` checks must tolerate reformatted output, and new code in patches must be
  lint-clean (curly braces, etc.); renamed directories need their `eslint.config.js` ignore entries renamed.
- Text rules miss these spellings unless handled: property accesses (`x?.qwen`), string escapes before a
  word (`\nqwen`, `\u2028qwen`), regex back-references (`'$1.qwen'`), URL-encoded slashes (`%2F.qwen`),
  glued shell flags (`-o.qwen`), gitignore negations, regex alternations (`(AGENTS|QWEN)\.md`), escaped
  dots, upper/lower-case variants, words glued after sanitizing. Length-capped tests break on the longer
  names (adjust anchored numbers, don't skip); tests where a sentence naming the product wraps, a
  table header fits or a dialog's row count depends on it are adjusted in `rebrand/name-length.mjs`.
- The `/review` footer rule (`review.mjs`) rewrites "Qwen<splice>Code" to "MariaDB Shell<splice>Agent";
  `submit.test` fillers are sized to the 240-character cap, so shrink them when the name grows.
- A rename must reach both writer and reader: e.g. the extension parses the daemon's
  `mariadb-shell-agent serve listening on` line with a regex literal.
- Don't remove Alibaba presets from `ALL_PROVIDERS`: internal code throws without them.
- Don't treat every QwenLM URL in tests as sample data: most assert the product's own constants.
- `.pnpmfile.mjs` must stay untouched (the lockfile pins its checksum).
- Release VS Code builds refuse Playwright's Electron mode (inspect fuse); drive an isolated instance with
  `--remote-debugging-port` + `chromium.connectOverCDP`, with a short `--user-data-dir` path (Unix socket
  limit ~103 chars).
- Theia webviews: open Theia on `localhost` (webviews use `<uuid>.webview.localhost`); Playwright's Firefox
  renders them blank, use Chrome (`channel: 'chrome'`). Locally the browser can reach the daemon anyway,
  so test the bridge by asserting zero direct browser requests to the daemon port.
- Extension tests import core's built `dist/`: after changing core (or after a rebrand), run
  `npm run build` in `packages/core` first, or they test stale presets.
- Test a rule or patch change end to end in a scratch worktree: `git worktree add --detach <dir>
  <upstream base>`, copy `mariadb/` in, `node mariadb/rebrand.mjs`, run the tests; reset with
  `git reset --hard && git clean -fd` (a half-reset tree makes the patches "conflict").
- Claude Code's auto mode blocks `git push --force-with-lease` (also `sync-upstream.sh --push`) unless
  the user explicitly grants force-push permission; otherwise sync locally and let the user run
  `! git push --force-with-lease NAS main`.
- Upstream release tags (`v0.26.x`) sit on release branches, not on `main`; sync to a `main` commit,
  which carries the same fixes (check with `git log <base>..upstream/main --grep='(#<PR>)'`).
- Upstream tests can rely on auto-update or usage statistics defaulting on without saying so, e.g. a
  concurrent dynamic import that misses the test's settings mock and reads empty real settings
  (`daemon-update.test`): skip them in `skipped-tests.mjs` under the default-off reasons, don't
  change the default.
- macOS has no `timeout` command; bound test runs inside the Node script instead.
- Claude plugins install from a local clone used as marketplace: `extensions install <repo>:<plugin>
  --consent` (MariaDB's `ai-plugins` repo: plugin `dev`). Hooks come from `hooks/hooks.json`, a `Bash`
  matcher matches `run_shell_command` (tool-name aliases), `${CLAUDE_PLUGIN_ROOT}` is substituted. The
  plugin's MCP/LSP launchers need `mariadb-shell` ≥ the version in `.mcp.json`; when missing they
  download it, which exceeds the 10 s MCP startup timeout: run the launcher once by hand. Check with
  `mcp list` and `--experimental-lsp -p "/lsp status"`.
- The bundled Linux arm64 ripgrep (upstream `packages/core/vendor/ripgrep`, static, jemalloc) crashes on
  16 KiB-page kernels such as the Raspberry Pi 5; the CLI falls back to a system `rg` (apt `ripgrep`),
  else to its built-in grep.
- The CLI bundle for quick tests: `npm run bundle` produces `dist/cli.js` (no `cli-entry.js`).
- `.claude/` is ignored by upstream's `.gitignore`; its files are tracked, but changes need `git add -f`.
- Measuring prompt caching: point a provider's `baseUrl` (in a temporary HOME's
  `.mariadb-shell-agent/settings.json`) at a recording stub, run the CLI (`-p`, `--continue`, or `--acp` with a
  small JSON-RPC client) to capture real requests, then replay them against the server with
  `max_tokens: 1` and read `usage.prompt_tokens_details.cached_tokens`. Network behaviour: a Node
  `--import` hook wrapping `dns.lookup` and `net.Socket.prototype.connect` logs every lookup and
  connection.
