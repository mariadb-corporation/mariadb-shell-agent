# MariaDB Code

MariaDB Code is a fork of [Qwen Code](https://github.com/QwenLM/qwen-code) with MariaDB branding,
including the VS Code extension (used in local VS Code and in `../mariadb-cloud-ide`). It follows
upstream closely: the fork is rebased onto upstream as soon as upstream moves.

## How the fork is kept rebase-friendly

Upstream files are never edited by hand. `main` is upstream plus two kinds of commits:

```
upstream/main
  <- fork commits: everything under mariadb/ (and real code fixes, if ever needed)
  <- "MariaDB branding (generated by mariadb/rebrand.mjs)"   (always the top commit)
```

- `mariadb/rebrand.mjs` makes every branding change (product name, extension identity, icons,
  Web Shell logo, terminal banner). Each rule fails loudly when upstream moves its anchor.
- The generated commit is thrown away and recreated on every sync, so it never conflicts.
- Fork commits only touch `mariadb/`, which upstream does not have, so they never conflict either.

Kept on purpose (renaming them would touch thousands of upstream lines for no user benefit):
command and setting ids (`qwen-code.*`), the config directory `~/.qwen`, `QWEN.md` context files,
`QWEN_*` environment variables, the `qwen` CLI binary, and the Qwen model and OAuth names.

## Remotes

| Remote     | URL                                             | Use                        |
| ---------- | ----------------------------------------------- | -------------------------- |
| `NAS`      | `https://github.com/mariadb-corporation/mariadb-shell-agent` | our fork; `main` tracks it |
| `upstream` | `https://github.com/QwenLM/qwen-code`           | fetch only (push disabled) |

## Sync with upstream

```sh
mariadb/sync-upstream.sh          # fetch, rebase, regenerate branding, pnpm install
mariadb/sync-upstream.sh --push   # ... and force-push main to NAS (history is rewritten)
```

The script also works when upstream has nothing new; run it after committing a change to
`mariadb/` (assets, `rebrand.mjs`) to regenerate the branding commit.

If `rebrand.mjs` stops with "anchor not found", upstream changed that spot: adapt the rule in
`mariadb/rebrand.mjs`, commit that as a fork commit (`git commit -- mariadb/`), discard the
partial branding (`git checkout -- . && git clean -fd -- packages scripts`) and run the sync again.

## Build the VS Code extension

```sh
corepack pnpm install --frozen-lockfile
mariadb/build-vsix.sh             # this machine, e.g. mariadb/dist/mariadb-code-<v>-darwin-arm64.vsix
mariadb/build-vsix.sh universal   # any platform, no node-pty: for the MariaDB Cloud IDE (Pi, arm64)
code --install-extension mariadb/dist/mariadb-code-<v>-darwin-arm64.vsix
```

In `../mariadb-cloud-ide`: `npm run plugin:mariadb-code` unpacks the newest universal build into
`plugins/`, then `npm run deploy:pi`.

The extension id is `MariaDB.mariadb-code`, so it installs beside upstream's Qwen Code Companion.
Both register the same command ids, so enable only one of them at a time.

## Icons

`mariadb/assets/` holds the icons, made from the MariaDB seal in
`../mariadb-shell/docs-ref/build/img/mariadb-logo-light.png` (traced to `seal-mono.svg`):
`app-icon.svg` (white seal on MariaDB dark teal `#003545`) and the PNG renders of it.
